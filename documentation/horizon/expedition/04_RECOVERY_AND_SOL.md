# Sol: bounded integration and debugging ownership

Use the existing local Codex task. Apply the supplied modules; do not regenerate the architecture or read the entire historical chat. The current workspace is authoritative for existing divergence fixes. This packet's historical fixture engine is never a source replacement.

## Integration conflict

The installer validates all planned writes before touching the checkout. `REVIEW_REQUIRED` means a hot-file anchor changed, a marker is partial, or a new filename already has different contents. Inspect that exact hunk plus the local diff. The intended hooks are documented in `integrate.cjs` and the two snippet files. Preserve all existing snapshot/continuation/allocator, bootstrap, warning, inventory, resource and cached-path fixes.

Adapting the small transform to the equivalent local seam is authorized; update its asset checksum in the extracted manifest and retain the original packet plus a patch recording your adaptation. Never copy fixture `agentEnvironment.ts`/renderer files into the game. Rerun installer and regression tests after adaptation. Hooks belong before/after the same semantic boundary, not merely near a similar string. If the current workspace already has an equivalent feature, reconcile interfaces rather than adding a duplicate competing controller or tracing loop.

`ALREADY_APPLIED` requires hook tokens as well as exact new payload bytes; partial application cannot be treated as success. On `ROLLBACK_CONFLICT`, preserve later changes and reconcile the affected hunk from receipt backups. Never force-reset the checkout. A stale packet-local application lock may be removed only after checking that its owner process is gone and no write is in progress.

## Environment

Use the checkout's supported Node/TypeScript and existing Python 3/Playwright environment. A missing `python` alias is not a code failure. Reuse installed Chrome. Honor normal sandbox permission approvals for local server/browser startup; permission denial is a blocked infrastructure gate, not a failed policy. Do not upgrade dependencies or download a new browser to repair project code.

Reuse one watcher or the approved one-cycle polling runner. Do not run production builds or multiple watchers. Stale/mixed capability markers require a fresh development bundle and reload of both game realms—not relaxed comparisons. Preserve the user's existing TypeScript 4.9 return casts/skipLibCheck. A source-type error is not fixed by weakening the test harness to `any` or suppressing project errors.

## Diagnosis loop

1. Save the exact seed, scenario, root/reproduction, explicit objective/goal, mode, budgets, contract and failing operation before changes. Add a compact entry to an external investigation log. Do not modify an active training run.
2. Reproduce the smallest failing case. In strategy cases compare reference and route-first from the **same untouched root**. For world intent use the logged sequence of verified live transitions; simulator traces cannot populate the ledger.
3. Trace the earliest disagreement to its producer/consumer. Add a regression that fails before the proposed repair. Make one minimal causal change. Rerun that regression and the original failure before the full suite.
4. Repeat without routine clarification. After three distinct falsified hypotheses without progress, preserve evidence and report a design blocker rather than accumulate speculative repairs. Do not wait for user confirmation merely to fix another ordinary setup error.
5. Once the focused case passes, run original planner, controller, Python/typecheck, and new reference/route-first multi-room gates. Inspect native ghost alignment under movement/resize and modal/Stop/replay behavior. Record baseline failures separately; do not erase or relabel them. Finish with diff check and the final patch/report.

## Specific classifications

- `PLANNING_*_MISMATCH`, repeated first-edge divergence, actual health loss, or unknown metric: keep the existing strict stop. Never edit expected identities, omit warnings/RNG/IDs/timers, assign guessed state, or continue a failed branch.
- `HORIZON_LEDGER_INVALID`: inspect the last verified transition, origin/arrival portal and episode identity. Do not infer a reverse edge, kill/collection, or visited room from geometry proximity alone. Preserve unresolved work and unknown heights. Capacity exhaustion must not silently drop history.
- `no-local-goal` / deferred work / strict zero-loss refusal: inspect objective candidates and locked/deferred status. It is not proof of unsolvability. Retry only after an explained material change or the explicit retry control. New spell/purchase/damage-trade rules are out of scope.
- Slow search: profile restore, capture/key, guard and step separately. Do not disable checks or make the old wall-clock budget larger until something passes. Route-first can legitimately lose on difficult routes; keep reference as fallback/default.
- Ghost misalignment: inspect the actual `mainCtx` transform at the native player draw boundary and canvas CSS/backing size. Never derive a camera from guessed player-centered coordinates. Rendering may fail independently; no ghost object may enter simulation/save state. An asset fallback is not proof of correct native sprite rendering.
- Frozen UI: main-thread simulation can delay paint. Preserve recorded traces and independent supervision. Do not slow simulation intentionally to show every animation. Worker extraction is a separately validated architecture phase.

## Non-negotiable boundaries

No PPO/reward/evaluator coupling, provider calls, new dependencies, production build, training, commits/push, replacement snapshot schema, synthetic Wait, health-policy change, skipped seed, weakened equality, or fabricated pass. No broad game-mechanics rewrite. No automatic writes to remote services or other Codex threads.

Final handoff: application receipt; changed files/local adaptation patch; focused and full gate results; actual-game versus synthetic results; paired operation/time measurements; any exact unresolved failure artifact. Keep the narrative short; attach evidence instead of long pasted logs.
